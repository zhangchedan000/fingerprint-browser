# 团队功能：本地模式、备用服务器、重新接入

> 2026-11-01 重写；同日备份改成「当班推给备用 + R2 只放当前和昨天」。v0.5.49 曾把团队功能整个停用；下一版（v0.5.50，开发分支 desktop-updates）起团队功能重新打开，改成「服务器连不上时可以进本地模式 + 一台备用服务器随时接班」。以后改团队功能、换服务器，先读这份。

## 一、现在的设计

## 二、平时怎么用、出事怎么办

- **新加坡挂了**：成员的启动器会先提示连不上，可以先进本地模式继续开窗口。主账号在团队页点「批量切换到 b.orengeshop.dpdns.org」（激活码在设备用时已经记住），大约 1～2 分钟后大家自动连到 B。最多丢新加坡挂掉前 1 分钟左右的改动。B 接班时用它自己手里的数据库副本和 R2 的哪个新用哪个，登录态从 R2 拉。
- **新加坡修好了，要切回来**：团队页「服务器」里新加坡那行点「批量切换到这台」（v0.5.52 起两台的激活码都自动记着）。旧版启动器：用左上角头像「连接其它服务器」，填 `https://temu.orenge.ccwu.cc` 和新加坡的激活码（新加坡 `.env` 的 `TEAM_SETUP_CODE`）。
- **新加坡挂了、R2 也连不上**：照样「批量切换」到 B：B 确认新加坡也连不上后，用自己存的数据库和登录态接班，R2 恢复后自动补写「谁当班」。新加坡还连得上时不让接班（防止两台同时当班）；新加坡后来修好开机，会问 B，看到 B 当班就自己变成待命。
- **两台都挂了**：本地模式继续用；服务器恢复后自动补传。R2 里有当前的数据库和登录态，任何一台新机器用 `install-standby.sh` 装好后都能「接班」。

## 三、服务器运维

- 装一台新的备用服务器（主机上是 nginx + certbot）：从公开仓库拿 `server/team`，`./install-standby.sh /opt/prism-team https://<域名>`。它会生成激活码、起容器（127.0.0.1:8090）、加 nginx 站点、申请证书。
- 更新一台正在用的服务器：`./update-server.sh /opt/prism-team https://<它自己的域名>`。先停服务、把 `pb_data` 打包到 `/opt/prism-team-pbdata-<时间>.tgz`、旧程序存 `rollback-<时间>/`，再换新程序启动。回退：把 rollback 里的文件拷回去 `docker compose up -d`。
- 本地全流程测试（不用真服务器）：`server/team/failover-test.sh`（两个本地 PocketBase + 本地目录当 R2）。

## 四、要注意

- 两台服务器**不能同时都当班写数据**（互相连不上时会出现两人同时开同一个店铺账号、登录状态互相覆盖、停用的成员还能用），所以永远只有当班标记里那一台写。
- 设备用和批量切换要主账号；成员只会自动跟随。
- 主账号电脑上记的激活码只用来切换；换了服务器的 `.env` 激活码要重新「设为备用」。
- 本地模式期间，同一个团队窗口别在两台电脑上同时用，否则连上后先传的那份为准。
