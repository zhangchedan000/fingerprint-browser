# 团队功能：停用说明和以后重新接入的方法

> 写于 2026-10-31，启动器 v0.5.49。以后要重新打开团队功能、或者换一个服务器，先读这份。

## 一、现在的状态（v0.5.49 起）

团队功能**停用了，但没有删**。

- 打开软件不要登录，直接进主界面。
- 软件不连任何团队服务器，一个请求都不发（有单元测试保证，见第五节）。
- 左边菜单不显示「团队」页。
- 开窗口、关窗口、改窗口、改 Cookie 都只在本机，不上锁、不上传、不同步。
- 以前从云端同步下来的窗口，现在是本机普通窗口：登录状态、指纹、代理都在，能开能改。

为什么停：团队服务器只有新加坡一台（甲骨文新加坡 `instance-20260730-1622`，`/opt/prism-team`，域名 `temu.orenge.ccwu.cc`）。启动器打开时要用它核对登录，每次开窗口最多每分钟再核对一次，它连不上，所有窗口都打不开。用户 2026-10-31 定：先停用团队功能，以后换成别的服务器再接。

## 二、开关在哪、关掉时改了什么

总开关只有一个：`src/shared/team.ts`

```ts
export const TEAM_FEATURE_ENABLED = false   // 改成 true 就重新打开团队功能
```

它管到的地方：

| 文件 | 关掉时的行为 |
| --- | --- |
| `src/main/index.ts` | `activeTeam.enabled = TEAM_FEATURE_ENABLED`，把开关交给团队管理器 |
| `src/main/team/team-manager.ts` | `enabled = false` 时：启动不恢复登录；`status()` 返回 `{ disabled: true }`；登录、注册、初始化、探测服务器，以及所有要连服务器的操作（成员、邀请、日志、备份、云端窗口列表等）都报「团队功能已停用」；开窗口前（`beforeLaunch`）、启动失败（`launchFailed`）、关窗口后（`afterExit`）、改窗口后（`afterLocalEdit`）、推 Cookie（`pushLoginState`）、同步（`scheduleSync` / `sync`）全部直接跳过；`assertEditable` 不再限制，所有窗口都能改 |
| `src/shared/team.ts` | `TeamStatus` 多了 `disabled` 字段 |
| `src/renderer/src/components/LoginGate.tsx` | `status.disabled` 时直接进主界面，也不去探测服务器 |
| `src/renderer/src/pages/registry.tsx` | `PAGES` 去掉 `team` 页；`pageDefinition` 找不到页面时回到第一页 |

团队管理器的类默认是 `enabled = true`（测试都按团队功能打开来测），只有 `index.ts` 按开关把它关掉。

## 三、保留下来的东西（重新接入时要用）

1. **代码全部保留**：`src/main/team/`（`team-api.ts` 和服务器通信、`team-manager.ts` 业务逻辑、`team-archive.ts` 登录状态打包、`team-extensions.ts`、`team-records.ts`、`team-ipc.ts`、`saved-passwords.ts`），界面 `src/renderer/src/pages/team/TeamPage.tsx`、`LoginGate.tsx`，服务器 `server/team/`（PocketBase 表结构、脚本、部署和恢复说明见 `server/team/README.md`）。
2. **每台电脑上的 `team.json`**（在数据目录里，和窗口数据放在一起）原样保留，停用时不改它，只读：
   - `server`：上次连的服务器地址（现在是 `https://temu.orenge.ccwu.cc`）；
   - `token`：上次的登录凭据（用系统凭据加密）；
   - `role`、`userId`：上次登录的账号；
   - `links`：本机窗口 ↔ 云端窗口的对应关系，每个窗口一条：`teamId`（云端记录 id）、`dataRev`（本机登录状态的版本）、`configRev`（本机配置的版本）、`pendingUpload`、`ownerId`。2026-10-31 查 Win11 电脑：7 条。
   - `removed`：本机删掉、云端还在的窗口。
3. **服务器和数据**：新加坡服务器还在跑（停用后没有人再连它），数据在 `/opt/prism-team/pb_data`（2026-10-31 约 20 MB）；异地备份在 Cloudflare R2（数据库有改动 1 分钟内传一份、保留 7 天；登录状态上传后 1 分钟内传；每天北京时间 03:30 完整同步）。从 R2 恢复：`server/team/r2-restore.sh`。

**注意**：停用期间在本机改的窗口（配置、登录状态）不会同步到云端，所以重新接入时云端那份可能比本机旧。见第四节第 4 步。

## 四、以后重新接入的步骤

### 情况 A：还用 PocketBase 这套服务器（新加坡那台，或者换一台机器部署同样的服务）

1. **准备服务器**
   - 还用新加坡那台：确认 `https://<域名>/api/health` 返回 `API is healthy`。
   - 换一台机器：按 `server/team/README.md` 的「部署」装好 Docker 服务。要保留原来的账号和团队窗口，就在新机器上用 `r2-restore.sh` 从 R2 恢复（数据库和登录状态都会回来，云端记录的 id 不变，各电脑 `team.json` 里的 `links` 照样对得上）；要从零开始，就不恢复，第一次连接时用初始化码建主账号。
2. **改启动器**
   - `src/shared/team.ts`：`TEAM_FEATURE_ENABLED = true`。
   - 换了域名：改 `src/main/team/team-manager.ts` 里的 `DEFAULT_TEAM_SERVER`。**还要处理旧地址**：各电脑的 `team.json` 里存着旧的 `server`，`status()` 优先用它（`this.file.server || DEFAULT_TEAM_SERVER`）。所以换域名时要加一段迁移：`initialize()` 里如果 `file.server` 是旧域名，就换成新的。新服务器是从 R2 恢复的，`token` 可能还能用，不能用的话会回到登录页重新登录。
   - 新服务器是从零开始的（没有恢复数据）：各电脑 `team.json` 里的 `links` 指向的云端记录不存在了，要加一段迁移把 `links` 和 `removed` 清空，否则开窗口时会报「这个团队窗口已被收回或删除」。清空后，第一次同步会把本机窗口当新窗口传上去。
3. **测试**：`npx vitest run`（团队相关测试默认就是打开状态）；`server/team/smoke-test.sh` 对服务器做冒烟测试；在两台电脑上实测：登录 → 打开团队窗口（上锁）→ 关闭（上传登录状态）→ 另一台打开（拉到最新登录状态）。
4. **停用期间本机改过的窗口**：按代码（`beforeLaunch`）：打开窗口时，云端的 `config_rev` / `data_rev` 比本机 `links` 里记的大，才用云端的覆盖本机；停用期间没人能改云端，所以单台电脑上的改动不会被覆盖，重新接入后关窗口时登录状态会照常传上去（配置要再改一次才会传，`afterLocalEdit`）。**会出问题的是同一个团队窗口在两台电脑上停用期间都用过**：重新接入后先关窗口的那台先传上去，另一台打开时会被它覆盖。所以重新接入时，同一个窗口只在一台电脑上先开、关一次，确认云端是想要的那份，再到别的电脑上用；或者先清空 `links`，把各台电脑的窗口当成新窗口重新上传（会变成两份）。具体选哪种，接入时和用户确认。
5. 出新版启动器（版本号、`release-notes/`），按 `当前进度.md` 的发布流程（分支构建通过后，在 Win11 电脑 `E:\prism-work\launcher` 打 tag 推上去）。

### 情况 B：换成别的平台（腾讯云开发、Supabase、Cloudflare 等）

启动器和服务器之间只通过 `src/main/team/team-api.ts` 的 `TeamApi` 类通信，`team-manager.ts` 只调用它的方法。换平台时：

1. 照着下表写一个新的 `TeamApi`（方法名、参数、返回值保持不变），`team-manager.ts` 基本不用动。
2. 新平台上要实现同样的规则（下表「必须保证」一栏），这些在 PocketBase 里是靠 `server/team/pb_hooks/*.pb.js` 和表的权限规则做的。
3. 把旧数据迁过去：从 R2 恢复出 PocketBase 的 SQLite 数据库和登录状态文件，再导入新平台；云端记录 id 变了，就按第 2 步的说明清空各电脑的 `links`，重新上传。

`TeamApi` 用到的接口（都在 `team-api.ts`，PocketBase 版本的路径）：

| 方法 | 现在的接口 | 作用 | 必须保证 |
| --- | --- | --- | --- |
| `status` | `GET /api/team/status` | 服务器在不在、有没有主账号、锁的时长 | 不用登录也能调 |
| `setup` | `POST /api/team/setup` | 用初始化码建主账号 | 只能成功一次 |
| `register` | `POST /api/team/register` | 用邀请码注册成员 | 邀请码一人一码、7 天有效、用后作废；乱试要限流 |
| `login` / `refresh` | `POST /api/collections/users/auth-with-password`、`auth-refresh` | 登录、续登录 | 输错 5 次停 15 分钟；被停用的账号续不了 |
| `listUsers` / `createMember` / `updateMember` / `removeMember` / `changePassword` | `users` 表 | 成员管理 | 只有主账号能管别人 |
| `listInvites` / `createInvite` / `revokeInvite` | `/api/team/invites` | 邀请码 | 只有主账号 |
| `listProfiles` / `getProfile` / `saveProfile` / `updateProfile` / `removeProfile` | `team_profiles` 表 | 云端窗口：配置（含代理和平台账号密码）、分配给谁、登录状态压缩包 | 成员只能看到分配给自己的；`config_rev` / `data_rev` 每次改都加 1 |
| `lock` / `heartbeat` / `unlock` | `POST /api/team/profiles/<id>/lock`、`heartbeat`、`unlock` | 打开窗口前上锁，开着时每 30 秒心跳，关了解锁 | 同一时间只能一台电脑占用；90 秒没心跳自动释放；上传登录状态前必须持有锁，而且版本号要对得上 |
| `listLocks` | `team_locks` 表 | 谁在用哪个窗口 | |
| `downloadData` | `POST /api/files/token` + 文件下载 | 下载登录状态压缩包 | 只有能看到这个窗口的人能下 |
| `logs` | `team_logs` 表 | 操作日志 | 只有主账号能看 |
| `serverInfo` / `listBackups` / `createBackup` / `removeBackup` / `downloadBackup` / `setOffsite` / `removeOffsite` | `/api/team/server`、`/api/team/backups`、`/api/team/offsite` | 服务器状态、备份、异地备份 | 只有主账号；换平台后可以不做，界面上对应按钮要隐藏 |

### 当时讨论过、还没做的增强（接入时可以一起考虑）

- **离线宽限**：服务器连不上（不是账号被停用）时，这台电脑最近 7 天成功登录过就照常能进、能开窗口，恢复后补传。
- **备用服务器**：两台同时在线，主服务器的改动同步到备用；靠 R2 上的「当班」标记保证只有一台在写；启动器知道两个地址，主的挂了自动切到备用。简化版（每分钟从 R2 同步、挂了 3 分钟后接班）估计半天，实时同步再加半天到一天。
- **不建议**两台服务器同时都能写：互相连不上时会出现两台电脑同时打开同一个店铺账号、登录状态互相覆盖、停用的成员还能用。
