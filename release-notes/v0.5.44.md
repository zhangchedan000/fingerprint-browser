## 改动

- **Windows 账户被锁**：Chrome 每个新的浏览器配置第一次启动时，会用空密码登录一次 Windows，看电脑有没有设开机密码（Chromium 源码 `password_manager_util_win.cc`）。设了密码的电脑上，每次都算一次「密码输错」；Windows 11 默认 10 分钟内输错 10 次就锁账户。启动器每个窗口是一个配置，每次检测也是一个新的临时配置，所以短时间内新建、检测十来个窗口，就可能把电脑的 Windows 账户锁住。
- 现在启动器每次运行只自己做一次和 Chrome 一样的检查（读这个 Windows 账户上次改密码的时间，再用空密码登录一次），把真实结果写进每个新配置（窗口第一次打开、检测、Cookie 管理之前；`Local State` 里的 `password_manager.os_password_blank` 和 `os_password_last_changed`，格式和 Chrome 自己写的一样），Chrome 就不会再去登录。设了密码的电脑每次运行启动器最多记 1 次密码输错（以前是每个新窗口、每次检测各 1 次），没设密码的电脑一次都不记。已经打开过的窗口保留 Chrome 自己记下的结果，不改。改了 Windows 密码以后 Chrome 会像以前一样自己再查一次。
- 这个值只在本地配置文件里，网页读不到，不影响指纹；写的是真实结果，窗口里 Chrome 保存的密码要不要先验证 Windows 密码，和正常 Chrome 一样。

## 验证

- Win11 电脑（prism15 156 内核）建一个设了密码的临时 Windows 用户，看它的「密码输错次数」：启动器自己的检查得到「有密码」，记 1 次；之后两个写好结果的新配置各启动一次，0 次；对照：什么都不写的新配置启动一次，又记 1 次。
- 同一台电脑的管理员账户（没设密码）：启动器的检查得到「空密码」，和 Chrome 自己查的一样，一次都不记；写的修改时间和 Chrome 自己写的只差那 1 分钟余量。
- 单元测试、类型检查全部通过。
