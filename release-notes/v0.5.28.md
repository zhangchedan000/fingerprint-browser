指纹浏览器 v0.5.28（Windows x64）。**团队云端同步更像在原来的电脑上**：书签、历史、自动填充、扩展和扩展里的数据、检测记录都跟着窗口走；编辑页的 Cookie 框能看到和修改窗口现在的 Cookie。内核不变，仍是 [prism9](https://github.com/zhangchedan000/prism-kernel-releases/releases/tag/prism9)。

## 改动

**团队云端同步**
- 关窗口上传、另一台电脑打开时，除了原来的登录状态（Cookie、本地存储、打开的标签页、网站权限、保存的密码），现在还带上：书签、浏览历史（含网站图标和常去网站）、自动填充。
- 扩展：窗口用的扩展（包括「所有窗口都启用」的）连同安装包一起带过去，另一台电脑没有就自动装上，有同一个就直接用；扩展里存的数据（chrome.storage、规则、状态）也带过去。
- 检测记录：代理检测、指纹检测、深度检测（带截图）、IP 评分，在另一台电脑打开编辑页就能看到上一台的结果。
- 缓存不同步（每台电脑自己重建），所以上传的内容不会因为缓存变大。

**扩展**
- 从这一版起导入的扩展会在它的 manifest 里加一个固定的 key，在每台电脑上的扩展 ID 都一样，所以扩展的全部数据都能同步。
- 这一版之前导入的扩展没有 key，为了不丢已有窗口里的扩展数据，不去改它：同步时把它 chrome.storage 的数据换到另一台电脑的扩展 ID 下，但它放在浏览器公共数据库里的数据（IndexedDB、localStorage）带不过去。需要完整同步的话，删掉后重新导入一次（重新导入后原来窗口里这个扩展的数据会变成新的）。

**Cookie**
- 编辑已保存的窗口时，Cookie 框里直接显示这个窗口现在的 Cookie（窗口要先关掉），可以改。改了保存后，窗口的 Cookie 换成框里的内容，并同步到云端；粘贴新的 Cookie 保存后也会同步到云端。同步失败会提示，Cookie 仍然保存在本机。
- 刚保存 Cookie 就点打开时，会等 Cookie 写完再打开。

**API 提取**
- 正在用的代理连不上时，点「检测」照实显示连不上，不再自动从链接换一个新的（要换就点「换一个 IP」）；打开窗口时连不上仍会自动换。

## 验证

- 在 Windows 实机上用 prism 内核（156）加载扩展，带 key 和不带 key 的扩展 ID 都和启动器算出来的一样。
- 单元测试：扩展 ID 的算法用 Chromium 源码里的测试值核对；一个团队窗口从 A 电脑到 B 电脑再回到 A 电脑，扩展自动安装、扩展数据、书签、历史、检测记录都在，回来时用 A 自己原来的扩展；旧扩展的数据换到 B 的扩展 ID 下。
- 两台电脑之间通过真实团队服务器的同步，这一版没有在实机上跑（测试用的启动器没有登录团队账号），以单元测试为准，实际使用中再确认。
