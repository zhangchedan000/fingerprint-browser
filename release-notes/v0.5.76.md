## 更新内核不再被卡住

- 以前更新内核时，要先把旧的内核文件夹改名挪开。输入法这类后台程序（比如搜狗输入法的云服务）在窗口里用过一次，就会一直占着内核文件夹，改名会失败，提示「内核文件夹正被其他程序占用」，要退出输入法或重启电脑才能更新。
- 现在更新时不改名任何文件夹：新版本装进内核文件夹里一个按时间命名的子文件夹，装好后新打开的窗口就用新版本。旧版本没人用了就自动删掉；还有程序占着的，等以后空闲（比如重启后）再自动清理。
- 已经装好的内核照常能用，下次更新时自动换成新的方式。
- 配套的内核 prism24 也从根上解决了：内核不再让自己的文件夹成为其他程序的「当前所在文件夹」，输入法等后台程序不会再占着内核文件夹。已经在后台占着旧内核文件夹的程序，要重启一次电脑才会放开。

## 内核列表少查 GitHub

- GitHub 对没登录的查询有限制（同一个网络出口每小时 60 次）。以前每次打开「下载内核」都去查两个项目，反复打开就会提示「查询次数用完了」。
- 现在查到的版本列表会记住 10 分钟，期间不重复查；GitHub 暂时拒绝或连不上时，先用上次查到的列表。
- 不再查旧的启动器项目（那里只有很早的内核，这个启动器已经不用），只查内核项目。

## 验证

- 单元测试 486 个、类型检查全部通过。新增：旧版本文件夹在没人用时删掉、有人用时留着下次再删；中断的安装留下的文件夹会清理；共用的字体包不受影响；版本列表 10 分钟内不重复查，GitHub 拒绝时用上次的列表。
- 在 Windows 上用测试版实测：让一个程序一直占着旧内核文件夹（和输入法后台程序一样），旧版启动器的做法这时会失败；新版先装回一个旧版本、再更新到最新，两次都成功，内核检查正常；结束占用程序、重启启动器后，旧文件夹被自动清掉。
