## 订阅节点检测不再误报失效

- 以前订阅节点要先在本机占一个本地端口才能用，一共 64 个，而且用过就一直占着，检测完、窗口关了都不还。订阅里节点多的时候，点「全部检测」，前 64 个检测完就把端口占满了，后面的节点还没连就报「同时使用的节点不能超过 64 个」，显示成「失效」。其实这些节点是通的，延迟和出口 IP 都测得到。
- 现在检测完马上归还端口，窗口关了也归还。窗口开着的时候它的端口不会给别的节点用，所以窗口不会跑到别的节点上。
- 上限也调大了：订阅节点 128 个，网络加速里固定节点 64 个。现在这个上限只限制「同时开着的窗口里一共用了多少个不同的节点」，几个窗口用同一个节点只算一个，检测不算。
- 之前被误报的节点，更新后在订阅页点一次「全部检测」，就会按实际情况重新显示。

## 订阅页表头和其他页面一样

- 订阅列表和节点列表都可以点表头排序：节点名、协议、出口 IP / 地区、延迟、状态、绑定窗口；订阅名、类型、节点数、绑定窗口、最后更新。
- 可以拖表头边缘改宽度、拖表头换位置；右上角「订阅列」「节点列」两个按钮可以隐藏列、恢复默认。设置按电脑记住，所有订阅的节点列表共用一套。

## 旧记录

- 删除订阅时，它下面没绑窗口的节点记录一起删掉；绑了窗口的照旧留着，窗口打开时提示重新选节点。
- 订阅里已经没有的节点（改名、删掉了）留下的记录不会自动删除，因为订阅临时拉不下来时节点也会暂时消失。订阅页右上角会出现「清理旧记录 N」，确认没用了再点。只删没绑窗口的，绑了窗口的会说明有几条没删。
- 左边栏「代理 IP」的数字只算页面上能看到的：代理加上订阅里现在有的节点，旧记录不算。

## 验证

- 单元测试 495 个、类型检查全部通过。新增：用真实的代理组件测试，节点端口在窗口或检测用完后归还、两个窗口用同一个节点时关掉一个不影响另一个、端口被占着时不会换成别的节点、只用一次的连接 1 分钟内不被挪用；窗口和检测的代理通道关闭时归还端口，打开失败也归还；旧记录一次删掉、绑了窗口的保留。
- 用测试版实测（独立的测试数据，不碰正在用的窗口）：140 个订阅节点（多于 128 个端口）每次 8 个全部检测完，没有一个报「不能超过」；左边栏数字等于节点数；节点列表按名称排序正确，表头可以拖宽度、拖位置；删除订阅时它没绑窗口的记录一起删掉；「清理旧记录」只删没绑窗口的。
